SOC Analyst Training & Methodology

Central SOC Principle

“An anomaly is a starting point for investigation, not proof of compromise.”

— Modern Network Defense & Triage Practice

Detection tells an analyst where to look. Investigation determines what actually happened. In enterprise security, legitimate software updates, database backups, network monitoring systems, and vulnerability scans frequently create high-volume or unusual traffic patterns that look suspicious on paper but are completely benign in context.

How to Think Like a SOC Analyst (7-Step Workflow)

  1. 1. Observe unusual behaviour: Identify anomalous spikes in volume, strange protocol distributions, or unexpected host communication.
  2. 2. Identify the source and destination: Pinpoint the IP addresses involved. Are they internal workstations, servers, or external internet hosts?
  3. 3. Determine which protocol is involved: Is it DNS, HTTP, ICMP, or unusual raw TCP? Does the protocol match expected business activity?
  4. 4. Establish whether the activity is expected: Check asset inventory. Is the source host an authorised vulnerability scanner, domain controller, or backup agent?
  5. 5. Look for supporting indicators: Correlate timing. Did this occur during a maintenance window or off-hours? Are multiple ports being targeted sequentially?
  6. 6. Correlate with other security telemetry: Cross-check endpoint logs (EDR/Sysmon), authentication logs, and firewall rules.
  7. 7. Decide whether further investigation is required: Close as benign/authorized maintenance, or escalate to active incident response.

How to Export Packets in Wireshark

  1. Step 1: Open Wireshark and capture traffic in an authorised testing environment.
  2. Step 2: Stop the capture when you have recorded the desired traffic flow.
  3. Step 3: In the top menu, navigate to File > Export Packet Dissections > As CSV...
  4. Step 4: Save the file (e.g., capture.csv) on your computer.
  5. Step 5: Upload or drag the file into this tool for triage.

Authorisation Notice: Only capture traffic from systems and networks you own or have explicit written authorisation to monitor. Capturing network packets on unauthorised networks may violate local laws and organizational policies.

Detection Engine Limitations (Version 1)

  • Metadata Only: CSV exports lack full packet payload bytes. Deep inspection and encrypted stream decodes cannot be performed from CSV summary data alone.
  • NAT Obfuscation: Network Address Translation may mask hundreds of internal hosts behind a single router IP address, inflating packet counts.
  • Environment Variance: A threshold of 50 packets is high for an idle IoT sensor, but tiny for a web server. Always tune thresholds to your specific environment.
  • Wireshark Column Layout: Port and TCP flag analysis depend on Wireshark's default Info and Protocol columns.
